# Словарь бренда платформы

Источник истины для канонических фраз. Скиллс `book-to-modes`, инструкция `docs/runbooks/add-new-book.md` и автопроверка `npm run check` сверяются с этим документом.

## Каноническая лексика

| Контекст | Каноническая фраза | Где |
|---|---|---|
| Название платформы / бренд | **Книжный Спарринг** | `landing_data.hero.tag`, ярлык карточки сравнения, тег над заголовком героя на лендах программ, упоминание в приветствии бота |
| Ярлык типа активности рядом с брендом | **Практика** | `landing_data.comparison.columns[*].role` для колонки «Книжный Спарринг» |
| Описание категории продукта | «AI-тренажёр» / «AI-тренажёры» | SEO meta-теги, FAQ-ответы, общие описания вида «AI-тренажёры по книгам», `<title>` главной |

## Запрещено в коде

Линтер `npm run check` падает, если находит эти фразы в полях ярлыков:

| Фраза | Где запрещена | Что вместо |
|---|---|---|
| `"name": "AI-тренажёр"` | в `landing_data.comparison.columns` (seed-SQL и фронтенд) | `"name": "Книжный Спарринг"` |
| `"name": "AI-ассистент"` | в `landing_data.comparison.columns` | `"name": "Книжный Спарринг"` |
| `"role": "Ежедневная практика"` | в `landing_data.comparison.columns` для колонки бренда | `"role": "Практика"` |
| `"hero_tag": "AI-тренажёр по книге"` | в `landing_data.hero.tag` для лендов программ | `"hero_tag": "Книжный Спарринг"` |

## Где «AI-тренажёр» допустим

Слово «AI-тренажёр» — это название категории продукта (как «онлайн-курс» или «приложение»). Оно допустимо там, где описывает _что это за продукт_, а не где ставит ярлык бренда:

- SEO `meta_title` и `meta_description`: «AI-тренажёр: Название книги — Автор» — это поисковый запрос, важен для Google/Яндекса.
- FAQ-вопросы и ответы: «Что такое AI-тренажёр по книге?» — естественное описание.
- Главная страница: `<title>` «Книжный Спарринг — AI-тренажёры по книгам».
- Юридические тексты (оферта, политика конфиденциальности).
- Описательный текст в `landing_data.comparison.conclusion` («AI-тренажёр — мост между книгой и кабинетом терапевта»).
- Описательный текст в hero_subtitle и social_proof.

## Что делать при изменении этого словаря

Если ты переименовываешь сквозную фразу платформы:

1. **Обнови этот файл** — добавь старую фразу в «Запрещено в коде», новую в «Каноническая лексика».
2. **Обнови скиллс** `[.claude/skills/book-to-modes/SKILL.md](../.claude/skills/book-to-modes/SKILL.md)` и `[.claude/skills/book-to-modes/references/PLATFORM_MAP.md](../.claude/skills/book-to-modes/references/PLATFORM_MAP.md)` — все шаблоны JSON и описания полей.
3. **Обнови инструкцию** `[docs/runbooks/add-new-book.md](runbooks/add-new-book.md)` — примеры JSON и комментарии.
4. **Обнови seed-файлы программ** `scripts/seed-*.sql` — чтобы при пересоздании БД с нуля сразу стояло правильно.
5. **Обнови БД через `jsonb_set`** (НЕ через полную перезапись `landing_data`).
6. **Расширь автопроверку** `scripts/check-hardcodes.sh` — добавь новую запрещённую фразу.
7. **Прогони `npm run check`** — должно пройти зелёным.

## Связь с правилами

- В `CLAUDE.md` есть правило про сквозные тексты — оно обязывает свериться с этим документом при каждом сквозном переименовании.
- При добавлении новой функции, попадающей в шаблон книги (новое поле в `landing_data`, новая колонка в `programs`) — обновить и этот словарь, и скиллс.
