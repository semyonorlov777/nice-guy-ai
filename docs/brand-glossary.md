# Словарь бренда платформы

Источник истины для канонических фраз. Скиллс `book-to-modes`, инструкция `docs/runbooks/add-new-book.md` и автопроверка `npm run check` сверяются с этим документом.

## Каноническая лексика

| Контекст | Каноническая фраза | Где |
|---|---|---|
| Название платформы / бренд | **Книжный Спарринг** | везде, где раньше писалось «AI-тренажёр» — meta-теги, FAQ, описания, hero_tag, ярлыки, юридические тексты |
| Ярлык типа активности рядом с брендом | **Практика** | `landing_data.comparison.columns[*].role` для колонки «Книжный Спарринг» |
| Слово «искусственный интеллект» в тексте | **ИИ** (русскими буквами) | везде, где раньше было «AI» как самостоятельное слово или префикс к существительному: «AI-ассистент» → «ИИ-ассистент», «AI помнит» → «ИИ помнит» |

## Запрещено в коде

Линтер `npm run check` падает, если находит эти фразы в seed-SQL и компонентах лендинга:

| Фраза | Что вместо |
|---|---|
| `AI-тренажёр` (и все падежи: AI-тренажёра, AI-тренажёру, AI-тренажёром и т.п.) | `Книжный Спарринг` |
| `AI-ассистент`, `AI-тренер`, `AI-коуч`, `AI-стратег`, `AI-редактор`, `AI-помощник`, `AI-автор` и любой `AI-<существительное>` | `ИИ-ассистент`, `ИИ-тренер` и т.д. (просто меняем латиницу на кириллицу) |
| `AI` как отдельное слово в тексте для пользователя («AI помнит», «общение с AI») | `ИИ` |
| `Nice Guy AI` (старое название платформы) | `Книжный Спарринг` |
| `Ежедневная практика` в `landing_data.comparison.columns[*].role` | `Практика` |

## Где «AI» допустимо

- В служебных комментариях кода (`// Stream with Vercel AI SDK`, `/* AI block insight */`) — это техническая разметка, пользователь не видит.
- В именах npm-пакетов и SDK (`@vercel/ai-sdk`, `Vercel AI Gateway`) — это бренды сторонних библиотек.
- В именах файлов компонентов (`AIMessage.tsx`) — внутренние идентификаторы.

## Что делать при изменении этого словаря

Если ты переименовываешь сквозную фразу платформы:

1. **Обнови этот файл** — добавь старую фразу в «Запрещено в коде», новую в «Каноническая лексика».
2. **Обнови скиллс** `[.claude/skills/book-to-modes/SKILL.md](../.claude/skills/book-to-modes/SKILL.md)` и `[.claude/skills/book-to-modes/references/PLATFORM_MAP.md](../.claude/skills/book-to-modes/references/PLATFORM_MAP.md)` — все шаблоны JSON и описания полей.
3. **Обнови инструкцию** `[docs/runbooks/add-new-book.md](runbooks/add-new-book.md)` — примеры JSON и комментарии.
4. **Обнови seed-файлы программ** `scripts/seed-*.sql` — чтобы при пересоздании БД с нуля сразу стояло правильно.
5. **Обнови БД через `jsonb_set` или `regexp_replace`** (НЕ через полную перезапись `landing_data`). Шаблон — `scripts/fix-comparison-brand.sql`.
6. **Расширь автопроверку** `scripts/check-hardcodes.sh` — добавь новую запрещённую фразу.
7. **Прогони `npm run check`** — должно пройти зелёным.

## Связь с правилами

- В `CLAUDE.md` есть правило про сквозные тексты — оно обязывает свериться с этим документом при каждом сквозном переименовании.
- При добавлении новой функции, попадающей в шаблон книги (новое поле в `landing_data`, новая колонка в `programs`) — обновить и этот словарь, и скиллс.
