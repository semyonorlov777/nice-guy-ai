# Changelog

Все заметные изменения платформы Nice Guy AI.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Добавлено
- **Мини-проект `mini/voice/` (маршрут `/voice`) — личный инструмент быстрой расшифровки голосовых заметок.** Зашёл по секретной ссылке → создал заметку → записал голос → получил готовый текст. В Chrome/Edge запись идёт через Web Speech API (бесплатно, real-time), в Safari fallback на OpenAI `gpt-4o-mini-transcribe`. Дополнительный канал — отдельный Telegram-бот: записал голосовое → бот пришёл текст в ответ и сохранил в чат «Telegram Inbox» в вебе. Single-user (доступ — секретная ссылка + `VOICE_OWNER_TG_CHAT_ID`), `noindex`. Изолированный мини: своя схема `voice` в Supabase, отдельные ENV `VOICE_BOT_TOKEN`/`VOICE_BOT_WEBHOOK_SECRET`/`VOICE_OWNER_TG_CHAT_ID`. Подробнее — `mini/voice/CLAUDE.md`.

### Исправлено
- **Вход через Telegram — имя теперь видно в профиле, аватар подтягивается, бот пишет тёплое приветствие.** Раньше после входа через бота в сайдбаре кабинета вместо имени показывался только `@username`, аватар оставался пустым, а бот отвечал сухим «Привет, СЕМЁН ОРЛОВ! Ты залогинен на Книжный Спарринг.» Три причины: (1) `ProfileMenu.tsx` ставил приоритет `@username` над `name` — теперь наоборот, имя на первой строке, `@username` уходит в подзаголовок dropdown'а; (2) `downloadAndUploadAvatar` падал с 400 от Supabase Storage — отправлял `Uint8Array` на POST, а storage-server для POST ожидает `multipart/form-data`, теперь оборачиваем в `Blob` (заодно добавили Sentry-логирование 400, чтобы такое ловить сразу); (3) сообщение бота переписано на тёплое («Готово, Семён 👋 Возвращайся на вкладку с сайтом — я уже тебя пропустил. Если поставишь фото в Telegram — оно подтянется в твой профиль на сайте.»), регистр имени нормализуется — `СЕМЁН ОРЛОВ` (если юзер так записал first/last_name в Telegram) приводится к `Семён Орлов`. Существующим Telegram-юзерам имена в `profiles` нормализованы одноразовой миграцией.

### Добавлено
- **Идентификатор аккаунта в профиле и в боковой панели.** Раньше после входа было непонятно, через какой способ ты залогинен — на экране показывалось только имя и тариф. Теперь под именем мелким серым текстом виден идентификатор: `@username` для Telegram-юзеров с username, реальный email для Google и Magic Link, `Telegram ID: …` для Telegram-юзеров без username. Фейковые служебные email вида `*@niceguy.local` (Telegram без username, Яндекс без email-scope) скрыты. То же самое показывается во второй строке профиль-меню в сайдбаре кабинета (раньше было хардкодное «Свободный»). Логика — `lib/user-identifier.ts:resolveUserIdentifier()`.

### Изменено
- **Чат: новая раскладка скролла как у ChatGPT / Claude.** Раньше переписка скроллилась в узкой колонке между неподвижными плашками — выглядело как «маленькое окошко в большом интерфейсе» и после отправки сообщения часть ответа AI была за пределами экрана. Теперь во всех трёх чатах (основной авторизованный, экран создания чата, чат на лендинге без логина): прокрутка идёт по всей доступной области, заголовок прилипает к верху, поле ввода — к низу. После отправки твоё сообщение «прыгает» к верху экрана, ответ AI начинается прямо под ним и читается с начала. Поведение прокрутки во время печати AI теперь умное — если ты сам прокрутил вверх, экран не дёргается. Под капотом: библиотека `use-stick-to-bottom` (Sam Denty / StackBlitz Labs, тот же код в bolt.new), `overflow-anchor: none` на списке сообщений, spacer-паттерн через `min-height: calc(100dvh - 220px)` на последнем сообщении. Подстраховки: `interactive-widget=resizes-content` в meta viewport, новый хук `useKeyboardInset` (VisualViewport polyfill для iOS Safari), новый хук `useTelegramMiniApp` (`WebApp.disableVerticalSwipes()` + swipe-классы — иначе свайп вниз начал бы закрывать приложение в Telegram). На лендинге spacer-паттерн отключён (`.landing-v3 { --chat-spacer-h: 0px }`) — чат там живёт в карточке, не на всю страницу. `aria-live="polite"` + `role="log"` теперь на всех трёх чатах для голосовых помощников.
- **Анкета пользователя подключена к «Пиши, сокращай» (первая итерация масштабирования после пилота на Гловере)** — старый чат-режим «Настройка тренажёра» (3 вопроса в чате с бейджем «Сначала это») заменён фуллскрин-анкетой `/program/pishi-sokraschay/anketa`: 3 шага с прогрессом и Skip, 4 чипа по уровням пирамиды Ильяхова + поле для своего ответа. Ответы хранятся user-level в `user_profile_responses` и автоматически попадают в три места: системный промпт каждого чата (блок «КТО ПЕРЕД ТОБОЙ»), welcome AI на хабе (плейсхолдер `{problem}` в новых ключах `anketa_only` / `anketa_and_test`), блок «Твой запрос — из анкеты» на странице портрета. Первый заход в `/program/pishi-sokraschay/hub` с пустой анкетой делает auto-redirect на анкету — раньше работало только для Гловера (захардкоженный `slug === DEFAULT_PROGRAM_SLUG`), теперь — для любого slug из каталога `AnketaProgramSlug`. `mode_template` записи `pishi_calibration` оставлены для аудита; только привязка к программе через `program_modes` снята.

### Изменено
- **Вход через Telegram — переключили на схему через бота с одноразовым кодом (`/start CODE`).** Прежняя цепочка из браузерных способов (legacy widget → OIDC SDK) больше не работает: Telegram в начале 2026 закрыли API на `oauth.telegram.org/auth`, эндпоинт отдаёт голое слово `deprecated`. Новый способ устроен так: клик на кнопку → `POST /api/auth/telegram/start` создаёт одноразовый код (TTL 10 минут, таблица `telegram_login_codes`) → юзер открывает `t.me/<bot>?start=<code>` в Telegram → жмёт START → наш webhook `POST /api/telegram/webhook` ловит сообщение, валидирует secret_token в header, сохраняет telegram_id и имя из update.from → сайт каждые 2с polls `GET /api/auth/telegram/poll?code=` → получает Supabase сессию и пускает в кабинет. Имя гарантированно приходит (из апдейта бота), фото — отдельной задачей через `getUserProfilePhotos` + загрузку в Storage (сейчас avatar остаётся пустым для новых юзеров). Старый виджет/OIDC код удалён (`app/api/auth/telegram/verify`, `lib/telegram-auth.ts`), заменён на новый `lib/telegram-login.ts`. Завели нового бота `@knizhny_sparringbot`. Полностью переписан [runbook](docs/runbooks/telegram-bot-setup.md). Бонус: бот теперь подписан на юзера после первого `/start` — слать уведомления через Bot API можно одним хелпером `sendBotMessage(chat_id, text)`.

### Исправлено
- **Вход через Telegram — промежуточная попытка вернуть OIDC после того, как Telegram выключили legacy widget.** Сначала откатили на OIDC SDK, но через несколько часов выяснили, что этот эндпоинт тоже мёртв. Поэтому полностью ушли на схему через бота — см. запись выше в «Изменено».
- **Вход через Telegram — починили CSP, который блокировал загрузку виджета.** Кнопка Telegram на `/auth` не появлялась — висела «Telegram загружается...» и через 6 секунд срабатывал fallback на Яндекс/Google. Корневая причина: после перехода с OIDC на legacy widget (PR #93) забыли обновить `Content-Security-Policy` в `next.config.ts` — `script-src` разрешал только `oauth.telegram.org` (домен OIDC), а сам виджет грузится с `telegram.org/js/telegram-widget.js`. Браузер молча блокировал скрипт. Добавили `telegram.org` в `script-src`. **Спустя несколько часов выяснилось, что legacy widget уже отключён самим Telegram** — см. предыдущую запись.
- **Вход через Telegram — диагностика, fallback при таймауте виджета, гибкая смена бота.** При входе через Telegram имя и фото из аккаунта подтягиваются в профиль автоматически (это было заложено в PR #93/#94, но без сопутствующих фиксов плохо проявлялось). Если кнопка Telegram не загрузилась за 6 секунд (обычная причина — домен сайта не привязан к боту в BotFather), вместо вечного «Telegram загружается...» теперь показывается понятное сообщение «Telegram-кнопка не загрузилась — войди через Яндекс, Google или email», а в Sentry приходит breadcrumb `telegram_widget_timeout`. Серверная верификация теперь различает причины ошибки (`hash_mismatch`, `expired`, `malformed`, `session_failed`) и шлёт их в Sentry как `tags.reason`, чтобы диагностировать на проде без гаданий. Username бота вынесен в env `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` — теперь сменить бота можно через Vercel Dashboard без коммита. Новый runbook `docs/runbooks/telegram-bot-setup.md` — пошагово что настроить в BotFather и на Vercel. Также защитили `telegram_username` и `avatar_url` от перезаписи NULL'ом: если у пользователя в Telegram нет username или фото — старые значения в профиле сохраняются, а не зануляются.

### Добавлено
- **Отдельная страница каталога программ `/programs`** — каталог больше не зашит в маркетинговый лендинг главной, а живёт на собственной странице. На карточке программы — бейдж «Бесплатно» или «490 ₽» (источник правды: `landing_data.pricing.is_paid` + `price_rub`), короткое описание книги и CTA «Открыть» / «Купить». Главная страница вместо полного каталога теперь показывает превью из трёх программ с кнопкой «Смотреть все программы →». Обновлены все навигационные точки: шапка лендинга, «Выбрать программу» в hero и финальном CTA, ссылка «Все книги» в BookSwitcher кабинета (теперь «Все программы» → `/programs` вместо `/#catalog`, который выкидывал залогиненного из кабинета на лендинг), и подвал. Платная программа — «Пиши, сокращай» за 490 ₽ — единственная отмечена как `is_paid: true`, остальные 12 бесплатные. Покупка пока не подключена: кнопка «Купить» ведёт на лендинг программы — реальный платёжный flow добавим отдельным этапом после согласования дизайна.
- **Программа «Борьба за внимание» (Максим Белоусов)** — третья маркетинговая книга на платформе после Ильяхова и Марк/Пирсон. 5 кастомных режимов на каркасе авторской методики «Работа с контекстами» из тренинга КЭС: Калибровка (3 вопроса → стартовый режим), Контексты (флагман — 5-столбцовая таблица: точка Б → 20 точек пласта А → решения/действия/усилители), Три линзы (триада физика-фокус-смысл), Эквалайзер (диагностика психология+инструменты+система), Чтение людей (КДМ — стоп-кадр, слова-артефакты, реверсивная психология). Плюс свободный чат и разговор с Максом — провокационный тон из тренинга, требование конкретики, стоицизм-фрейм. Главная цитата автора: «Не к миллиону рублей стремиться, а к контексту, в котором миллион приходит». Системные промпты учитывают 8 типов неэресурсных контекстов (угождение / доказание / избегание / жертва / война / недостаточность / перекладывание ответственности / чувство долга-вины).
- **Блок «Что делать с этим» на странице результатов теста по Гловеру** — для авторизованного владельца результата под зонами фокуса появляется один спокойный призыв с кнопкой «Начать/Продолжить с упражнения N». Текст автоматически адаптируется под 4 сценария: новичок (начни с 1), активный на упражнении N, дошёл до N но не открыл, прошёл всё. Зоны фокуса со старыми кликабельными ссылками на конкретные упражнения сохраняются. Применяется только к программе nice-guy (другие тесты не затронуты).

### Изменено
- **Промпты программы «Подсознание может всё» (Кехо) — теперь явно используют данные теста и кросс-режимные переменные.** По итогам аудита: в каждый из 7 кастомных режимов (Теория, Деконструктор убеждений, Мастер визуализации, Конструктор аффирмаций, Закладка чувств, Альбом побед, Лаборатория возможностей) добавлен блок «Использование контекста» — AI больше не спрашивает заново ту же цель, если её уже разбирали в смежном режиме (например, в «Мастере визуализации» подхватывает новое убеждение из «Деконструктора убеждений»), и упоминает уровень пользователя по релевантной шкале теста (без чисел) в первой реплике. Также режим «Лаборатория возможностей» переименован с ЭКЗАМЕН в ВОРКШОП — соответствует содержанию (челлендж через сократический диалог, не классический экзамен).

### Исправлено
- **Блок «С чего начать» в результатах теста «Архетип бренда и личности» теперь показывает архетипы и проценты, а не «1 — 0%»** — раньше две карточки сливались в одно сообщение с одинаковым текстом и нулевыми процентами. Корневая причина: промпт `archetype-test` намеренно выдавал расширенный формат (`headline` / `body` / `action_route` для перехода в режим «Артишок»), а компонент `TopZones` ждал минимальный (`scale_key + action_text`) и не отображал заголовок, абзац и кнопку-CTA. Расширили компонент под оба формата, нормализатор `normalizeInterpretation` теперь резолвит legacy-поле `archetype` (русское имя) в `scale_key` через инверсию названий шкал — старые результаты в БД отображаются корректно без регенерации. Промпт в БД переделан выдавать сразу `scale_key`. Регрессия EQ 2.0, issp-test и других тестов не затронута. Обновлены docs/books/heroes-and-outlaws-system-prompts.md и скилл book-to-modes (новый раздел «Формат top_zones» с двумя шаблонами для будущих книг).
- **Демо-чат на лендингах пяти программ — Герой и Бунтарь, Пиши-сокращай, Радикальное прощение, Терапия нового решения, Семь принципов — раньше показывал экран «Что-то пошло не так» и не давал зарегистрироваться.** Системная причина: для новых программ стартовые кнопки чата в базе хранятся в новом формате (различение обычных и «безопасный выход»), а компонент анонимного чата ждал старый формат-список строк — на новых данных рендер падал и пробивал к глобальному экрану ошибки. Починка: вынес общий нормализатор формата кнопок в `lib/chat/normalize-quick-replies.ts` (раньше эта логика дублировалась в трёх местах), подключил его в `AnonymousChat`, обернул блок чата на лендинге в `ChatErrorBoundary` — теперь любая будущая ошибка покажет локальное «Ошибка загрузки чата», а не глобальный экран. Линтер `npm run check:chats` теперь проверяет и поле `anonymous_quick_replies` — слепая зона, через которую новые seed-файлы попадали в прод без предупреждения.
- **Демо-чат «7 принципов» теперь стабильно обращается на «ты» и даёт «ёлочки» в кавычках** — усилены правила в `anonymous_system_prompt` для seven-principles: критический блок про «ты»/«вы» с обоих сторон (правильно/неправильно), counterexample «варианты без кавычек ≠ кнопки», явный список запрещённых формулировок («Похоже, вы столкнулись», «вам не хватает», «у вас в паре»). Раньше каждый второй ответ срывался на «вы» или варианты выводились plain text без «ёлочек», теперь все 5 проверочных ответов содержат принцип Готтмана + 3-4 «ёлочки» в кавычках + обращение на «ты».
- **Возврат на страницу книги после входа** — кликнув «Войти» с лендинга программы, пользователь теперь возвращается в кабинет этой же программы, а не на главную. Адрес возврата корректно передаётся через все способы входа: Telegram, Яндекс, Google, письмо со ссылкой, прямой адрес `/auth?redirect=`. Защита от подделки адреса встроена в общий проверочный список.
- **Dev-логин (`/api/auth/dev-login`) больше не падает с «Invalid login credentials»** после ротации `SUPABASE_SERVICE_ROLE_KEY`. Раньше юзер `dev_test@niceguy.local` оставался в БД со старым паролем, и каждый новый запуск dev-окружения вручную чинился через удаление юзера. Теперь при первом провале логина роут сам обновляет пароль через admin API и переподписывается заново. Только в dev-окружении.

### Добавлено
- **Программа «7 принципов крепкого и счастливого брака» (Готтман)** — 8-я книга платформы. 7 содержательных режимов: Карта любви, Разбор ссоры (4 всадника), Репетиция разговора (мягкий старт), Восхищение, Скрытая мечта (тупик), Смысл пары (4 столпа), плюс свободный чат и разговор с Готтманом
- **Тест «Карта брака» по 7 принципам Готтмана** — 28 вопросов, 7 шкал, навыковый формат (`higher_is_better`). Уровни Зона роста → Развивается → Устойчиво → Сильная сторона. Утверждения — из авторских опросников Готтмана к каждому принципу
- **Восьмая программа «Пиши, сокращай»** (Максим Ильяхов и Людмила Сарычева) — первая на платформе книга не по психологии, а по навыку: редактура текста, информационный стиль, копирайтинг. 7 чат-режимов на каркасе пирамиды коммуникации Ильяхова (царь горы → стоп-слова): «Настройка тренажёра», «Зачем этот текст», «Сформулируй мысль», «Структура и заголовки», «Очисти от стоп-слов», «Разбор моего текста», «Тренажёр До/После» + свободный чат + разговор с Ильяховым. Тон — дерзкий-коуч (Ильяхов из видео-курса), не «бережный наставник».
- **Новый паттерн «Калибровка»** — вместо классического ликерт-теста короткий 3-вопросный onboarding-режим (`pishi_calibration`).
