2. **Темы по сферам жизни ≠ шкалы теста 1:1** — натянутый маппинг (Деньги→Изобилие, Здоровье→Визуализация, Отношения→Благодарность, Творчество→Контроль мыслей). Шкала `mp_affirmations` без темы — сознательный выбор (универсальная техника).
3. **4 режима-воркшопа подряд** (mp_visualization/mp_affirmations/mp_imprinting/mp_victory_album) — каждая техника Кехо как самостоятельная практика. Это нарушает «5 базовых архетипов + 1-2 подвида» из REFERENCE.md, но обосновано книгой.

**Проблема:** В секции «КРОСС-РЕЖИМНАЯ СВЯЗКА» каждого промпта зафиксированы имена переменных (`new_belief`, `visualized_scene`, `feeling_anchor` и т.д.), но в тексте логики диалога нет явной инструкции «если в контексте есть `new_belief` — используй его при построении сцены». Сейчас это работает через общий блок «{{cross_mode_data}} — данные из других режимов» в programs.system_prompt, но индивидуальные режимы могут не учесть переданные данные.
**Решение:** В каждом промпте-получателе добавить 1-2 предложения в фазу «ФАЗЫ ДИАЛОГА» с явным упоминанием: «Если есть `new_belief` из режима «Деконструктор убеждений» — стартуй сцену с этого убеждения, не спрашивай заново». Точечные правки SQL через `UPDATE program_modes SET system_prompt = ... WHERE ...`.
**Трудозатраты:** 30 мин (правка 7 промптов + SQL-миграция + деплой)
**Приоритет:** 2

#### E3 — Явная инструкция использовать данные теста в режимах

**Статус:** ⚠️
**Проблема:** В `programs.system_prompt` есть фраза «Если из теста переданы баллы — используй их для приоритизации режимов», но индивидуальные промпты режимов не упоминают данные теста явно. `appendTestScores()` инжектит JSON в любой системный промпт, и AI его видит, но без явной инструкции в режиме может проигнорировать.
**Решение:** В каждый промпт режима добавить строку в «БАЗА ПО ТЕМЕ»: «Если есть данные теста — режим mp_X показал у пользователя уровень Y, упомяни это в первой реплике (без чисел)». Эффект — персонализация чувствуется с первого сообщения. Альтернатива — оставить как есть и доверить интуиции модели.
**Трудозатраты:** 15 мин
**Приоритет:** 2

#### G3+G4 — MIND_POWER_SYSTEM_PROMPTS.md и MODE_DETAILS.md

**Статус:** ⚠️
**Проблема:** Source of truth промптов — seed-SQL (`scripts/seed-mind-power*.sql`), что усложняет ревью. Сводная таблица переменных кросс-связок также отсутствует.
**Решение:** Один из вариантов:
- (a) Принять SQL как единственный source of truth — обновить чеклист G3/G4: «промпты живут в seed-SQL, отдельный MD необязателен»
- (b) Сгенерировать `docs/programs/mind-power-prompts.md` автоматически из БД (скрипт `npm run dump:prompts -- --slug=mind-power`) — даёт review-friendly view без рассинхрона
**Трудозатраты:** (a) 5 мин на правку чеклиста, (b) 1-2 часа на скрипт
**Приоритет:** 2 (улучшение качества жизни)

### Приоритет 3 (косметика)

#### H5 — mp_problem_lab помечен как ЭКЗАМЕН, но это челлендж-сессия

**Статус:** ⚠️
**Проблема:** `welcome_mode_label = "ЭКЗАМЕН"`, но в промпте mp_problem_lab нет адаптивной сложности и метакогнитивной калибровки — классических признаков экзаменационного режима. Это сократический челлендж-партнёр через 6 стратегий творчества.
**Решение:** Два варианта:
- (a) Переименовать `welcome_mode_label` в `ВОРКШОП` или `ЧЕЛЛЕНДЖ` (новый тип). SQL: `UPDATE program_modes SET welcome_mode_label = 'ВОРКШОП' WHERE ...`. Соответствие с чеклистом H5 станет «⬜ неприменимо»
- (b) Оставить как есть — лейбл «ЭКЗАМЕН» здесь метафоричен («проверь как ты видишь возможности»). Уточнить в чеклисте, что экзамен ≠ обязательно сложность-метрика
**Трудозатраты:** 5 мин (SQL) или 5 мин (правка чеклиста)
**Приоритет:** 3

#### I1+I2 — Визуальная проверка хаба и теста

## Новые правила для CHECKLIST.md (предложения, не применено)

Эти наблюдения возникли во время аудита mind-power. Решение о добавлении — за заказчиком.

### Предложение 1: B9 — допустить welcome_replies = [] для test-mode_template

**Контекст:** Текущий B9 проверяет `welcome_replies — массив объектов {text, type}, последний — type: "exit"`. Для tool/chat-режимов это корректно. Но для `test_*` mode_template (карточка теста на хабе) `welcome_replies = []` — норма: у теста свой `WelcomeScreen` из `ui_config.welcome_*`, replies для NewChatScreen не нужны.

В mind-power test_mind-power-test содержит `welcome_replies: []` и `welcome_title: null` — это работает корректно (карточка теста не рендерится через NewChatScreen). Если строго применять B9 — ставится ⚠️ ложно-положительно.

**Предлагаемая правка B9:** «`welcome_replies` — массив объектов `{text, type}`, последний — `type: "exit"`. **Исключение:** для mode_template с `is_chat_based=false` и `route_suffix` начинается с `/test/` — `welcome_replies` может быть пустым (`[]`), welcome берётся из `test_configs.ui_config.welcome_*`».

### Предложение 2: Новый пункт I4 — WebFetch недостаточен для JS-рендеренного контента

**Контекст:** WebFetch на `/test/[testSlug]` извлекает только статический HTML head — контент гидрируется React в браузере. Чеклист I2 («3 test-состояния») в текущей формулировке предполагает что проверка возможна без браузера, но это не так.

**Предлагаемая правка:** Либо переформулировать I1/I2 как «БД содержит корректные данные для всех состояний» (БД-проверка), либо добавить I4: «Для JS-рендеренных страниц (тест, хаб) — визуальная проверка возможна только через браузер (`npm run dev` + dev-login). WebFetch вернёт пустой контент». Это сэкономит время следующим аудитам.

### Предложение 3: Новый пункт H7 — Соответствие welcome_mode_label содержанию промпта

**Контекст:** В mind-power `mp_problem_lab.welcome_mode_label = "ЭКЗАМЕН"`, но промпт описывает челлендж-сессию через сократический диалог, не классический экзамен с адаптивной сложностью. Чеклист H5 проверяет «адаптивную сложность» для всех с лейблом ЭКЗАМЕН — но «экзамен» может быть метафорическим.

**Предлагаемая правка H7:** «`welcome_mode_label` должен соответствовать содержанию промпта. Лейблы: ЛЕКЦИЯ (сократический метод вопрос-ответ), АНАЛИЗ (диагностика паттернов), ВОРКШОП (пошаговая практика), РОЛЕВАЯ (играй роль X), ЭКЗАМЕН (адаптивная сложность + калибровка + фидбэк через концепции). Если промпт — челлендж через сократический диалог без адаптивности → ВОРКШОП, не ЭКЗАМЕН».

### Предложение 4: Новый пункт A11 — anonymous_system_prompt содержит блоки А+Б+В+Д+Е

**Контекст:** Анонимный промпт mind-power содержит все требуемые блоки (А «Обращение», Б «Запрет приветствий», В «Quick replies», Д «Структура трёх обменов с называнием концепта», Е «Quick replies критическое правило с контрпримером без кавычек»). Это критично — без блока Д анонимный AI не назовёт концепты книги по имени; без блока Е будет писать варианты без «ёлочек».

Сейчас в чеклисте проверки anonymous_system_prompt нет — он не упомянут в A8/A9/A10. Это слепое пятно.

**Предлагаемая правка A11:** «`programs.anonymous_system_prompt` содержит ВСЕ блоки: А «ОБРАЩЕНИЕ», Б «ЗАПРЕТ ПРИВЕТСТВИЙ», В «Quick replies — КРИТИЧЕСКОЕ ПРАВИЛО» (укороченный с контрпримером «без кавычек»), **Д «СТРУКТУРА ПЕРВОГО ОТВЕТА» с явным «ОБЯЗАТЕЛЬНО назови один из ключевых концептов книги по имени»**, **Е если контрпример без кавычек — обязателен**. Дополнительно: `programs.anonymous_quick_replies` — массив объектов `{text, type}`, последний `type: "exit"`».
