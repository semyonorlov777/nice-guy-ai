# Конспект решений: 7 навыков высокоэффективных людей (Кови)

**Slug:** `seven-habits`
**Тип:** Психология/личное развитие (этика характера, парадигма, эффективность)
**Категория:** `psychology` (10-я книга в группе)
**Дата:** Май 2026 — первая one-shot книга через обновлённый скилл с анкетой

## Что особенного

Это **первая книга**, добавленная в платформу через скилл `book-to-modes` **сразу с анкетой пользователя** (Этап 2.5) в одном проходе. До этого анкета добавлялась постфактум на 2 пилотные книги (`nice-guy`, `pishi-sokraschay`).

Цель — проверить one-shot пайплайн: книга → режимы → темы → анкета → hub-messages с плейсхолдерами — всё в одном PR без последующих fix-*.sql.

## Что сработало

1. **One-shot пайплайн оправдан.** Все 4 артефакта (программа + режимы + темы + анкета) применились через MCP Supabase за одну сессию. Не пришлось патчить hub_messages отдельным seed (как делали для nice-guy через `seed-anketa-hub-messages.sql`).

2. **Лекция как сократический диалог, не как пересказ.** Для книги Кови — концепции абстрактны (парадигма, P/PC), но усваиваются только на примере пользователя. Промпт sh_theory выстроен как 4 фазы вопросов «на твоём материале», а не «сейчас расскажу про…».

3. **Воркшоп с артефактом в портрете.** sh_personal_mission генерирует черновик в 3-5 предложениях, который сохраняется в портрет. Это лучше чем «дать готовый шаблон» — пользователь получает свою первую версию через диалог.

4. **Ролевая с двойной ролью + 💡-маркер.** sh_empathic_listening: Система играет собеседника + после каждой реплики пользователя даёт разбор через 💡. Паттерн из nice-guy (Тренировка границ), но адаптирован под Навык 5 — типы автобиографических ответов как чёткая категоризация.

5. **AI-фильтр тем без хардкода.** Не делал маппинг чип → тема. Gemini Flash в `theme-relevance.ts` сам выбирает 2-4 из 6 тем по ответам анкеты. Кеш в `anketa_theme_relevance` уже работает. Гибче и проще поддерживать.

6. **Заглушка `returning_test`** — для прохождения линтера `hub-messages-key-missing`, который требует все 3 канонических ключа. Просто дублирует `returning_notest` для недостижимого без теста состояния.

## Что пришлось доизобретать

1. **Колонка `chat_type` в `program_modes` — её нет.** В первой версии seed-seven-habits-modes.sql я вставлял `chat_type` в `program_modes` INSERT (по аналогии с моим пониманием из плана). Линтер БД отверг: `chat_type` живёт в `mode_templates`, в `program_modes` подтягивается join'ом. Пришлось переделать.
   → **Урок:** перед написанием seed для нового типа INSERT — `mcp__supabase__list_tables(verbose=true)` или `SELECT column_name FROM information_schema.columns`. Реальная схема ≠ ожидания.

2. **Hardcoded slug в `hub/page.tsx:103`.** Линия проверяла `slug === DEFAULT_PROGRAM_SLUG` (только nice-guy). Без правки на `isAnketaProgram(slug)` редирект на анкету для seven-habits не сработал бы. Это критическая правка для любой новой anketa-программы.
   → **Урок:** при добавлении нового slug в `AnketaProgramSlug` — обязательно проверить, что нет других мест с hardcoded slug. В этот раз нашли только одну точку, но в будущем может появиться больше.

3. **Линтер ловит вложенные «ёлочки» в reply.** Текст `«Что такое «парадигма» и при чём тут эффективность?»` — парсер парсит регекспом до первого `»`, текст обрежется. Пришлось убирать внутренние кавычки.
   → **Урок:** при тематических reply, где упоминается термин — НЕ кавычить термин внутри «ёлочек». Лучше курсивом в стиле «Что такое парадигма» (без кавычек термина) или переформулировать.

4. **Warning про `<em>` в personas.title.** Линтер ловит HTML-теги в plain-text полях. У меня было `personas.title = "Для тех, кто понимает: техники <em>работают только на характере</em>"`. Убрал `<em>`. Это plain-text поле, не поддерживает разметку.

5. **«Этика характера» как отдельный концепт в main_concepts.** В первой версии я её упомянул только связно с «Парадигмой» в anonymous_system_prompt. Линтер `anonymous-missing-main-concept` потребовал упомянуть явно. Решил добавив составную формулировку: «**Парадигма** и **Этика характера** (Часть 1)…».

## Что заняло больше всего времени

1. **Чтение книги Кови частями + написание system_prompt каждого режима (~90 мин).** Книга 11384 строки, ~1.2 МБ — Read'ом пришлось брать кусками. Самые важные главы: Навык 1 (Круг влияния, проактивная речь), Навык 2 (личная миссия, центры жизни), Навык 3 (4 квадрата), Навык 5 (4 типа автобиографических, 4 стадии эмпатии).

2. **Дизайн system_prompt с 4 кирпичами + специфика режима.** Каждый промпт ~5-8КБ. Все самодостаточны (не наследуют от `programs.system_prompt`). Линтер `check:chats` строго следит за наличием кирпичей А-Г в КАЖДОМ промпте.

3. **Скачивание + сжатие фото Кови (~10 мин).** Wikimedia Commons блокировал URL-thumbnails с нестандартными размерами (400 на 800px/640px endpoint). Пришлось качать оригинал 9 МБ, сжимать через System.Drawing на PowerShell до 1200×800px @ quality 95 (получилось 180 КБ). Это нормально для нашего лимита ≥100 КБ.

## Специфика книги

- **Книга-концепция, не книга-практикум.** В отличие от Гловера (46 нумерованных упражнений), у Кови нет «упражнений 1-N». Есть «Практические предложения» в конце каждого навыка — это вопросы для рефлексии, но не сценарий чата.
- **Тон Система — спокойный аналитик, не коуч.** Кови сам не любил коуч-язык. Промпты явно запрещают «прокачай», «раскрой потенциал».
- **Метафоры Кови — крючки для запоминания.** Карта Чикаго/территория Детройта (парадигма), курица и яйца (Р/РС), фермер не нагонит весной не посеянное. Используются во всех режимах.
- **Истории Кови — кейс с сыном в школе.** В books главный личный кейс автора, через который он пришёл к Этике Характера. В режиме author_chat обязательно к использованию.
- **8 концептов в main_concepts.** Не 5-7 как в других книгах — у Кови богатая система: Парадигма, Этика характера, Круг влияния, Личная миссия, Квадраты времени, Эмпатическое слушание, Эмоциональный банковский счёт, Заточка пилы.

## Уроки для следующих one-shot книг с анкетой

1. **Сначала проверь схему БД, потом пиши seed.** Особенно для нового типа INSERT (program_modes vs program_themes — разные колонки!).

2. **Расширение `AnketaProgramSlug` ≠ работающая анкета.** Минимум ещё одна правка нужна в `hub/page.tsx` (`isAnketaProgram(slug)` вместо `DEFAULT_PROGRAM_SLUG`). Возможно появятся другие точки — добавляй чеклист в скилл.

3. **Линтер `check:chats` — главный союзник.** Запускай его сразу после первого INSERT в БД, не в конце. Errors быстро отлавливаются и стоят 2-3 точечных UPDATE'а.

4. **Не копируй `{{cross_mode_data}}` в новые промпты.** Линтер `cross-mode-data-placeholder` ловит это как warning. Runtime подмешивает кросс-режимные данные сам — placeholder в seed не нужен.

5. **Hub_messages с 4 ключами (не 5).** Без теста состояние `anketa_and_test` недостижимо, можно опустить. `returning_test` — заглушка (дублируй `returning_notest`).

6. **Маппинг анкета → темы через AI работает.** Не плоди хардкод. Gemini Flash + кеш справляются.
