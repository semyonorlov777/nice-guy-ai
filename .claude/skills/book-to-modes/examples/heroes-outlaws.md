# Конспект решений: Герой и Бунтарь (Маргарет Марк, Кэрол Пирсон)

**Slug:** `heroes-and-outlaws`
**Тест slug:** `archetype-test`
**Тип:** Маркетинг/брендинг + психология архетипов (Юнг, Пирсон)
**Объединение книг:** нет (одна книга, хотя у Пирсон есть «Hero Within», «Awakening the Heroes Within» — концепции из них подмешиваются в режим «Твой личный архетип» и в author_chat)
**Дата:** Май 2026 (девятая книга платформы; **вторая не-психологическая** после «Пиши, сокращай»; **третий навыковый тест** после Бакирова и Бредберри)

## Книга

Маргарет Марк, Кэрол С. Пирсон. «The Hero and the Outlaw: Building Extraordinary Brands Through the Power of Archetypes». McGraw-Hill, 2001 / Питер, 2005. 336 стр. Классика брендинга.

## Особенность задачи

Первая книга про **бренды**, не про самого человека (хотя система Пирсон работает и для самопознания — поэтому встроен режим «Твой личный архетип»). Это шире, чем «Пиши, сокращай» (там был узкий навык — копирайтинг). Здесь — система ценностей, которую можно применить к продукту, компании, личному бренду или к самому себе.

## Главное архитектурное решение: НЕЙТРАЛЬНЫЙ ПРОФИЛЬ КАК ТРЕТИЙ ФОРМАТ ТЕСТА

До этой книги на платформе было два формата теста:
- **Диагностический** (`lower_is_better`): ISSP, GPP — высокий балл = выраженность паттерна = зона роста
- **Навыковый** (`higher_is_better`): hypnosis-test, eq-test — высокий балл = владение навыком = ресурс

Здесь нужен **третий формат — нейтральный профиль**: 12 архетипов не «лучше» или «хуже» — это просто разные сюжеты. Ни один из них не «правильный». PMAI Пирсон работает именно так.

**Решение:** взял `higher_is_better` как ближайший существующий формат + переинтерпретация. Высокий балл по архетипу = «архетип выражен в тебе как ресурс», низкий = «архетип в тени, в спящем состоянии». Уровни: «В тени / Зарождающийся / Осознанный / Доминирующий» (вместо «Новичок/Развивающийся/Уверенный/Мастер» Бакирова).

Дополнительно — главный экран результатов показывает **топ-2 архетипа из 12** как «твой профиль», а не уровни по каждой шкале. Это даёт читателю ясный сигнал, не перегружая. Радар с 12 точками — для тех, кто хочет деталей.

В UI ничего не пришлось менять — RadarChart и TestResultsPage уже поддерживали `score_direction` после Бакирова. Регрессия ISSP/GPP/hypnosis-test/eq-test не затронута.

**Прецедент для будущих книг:** для тестов на типологию/профиль (16personalities, MBTI, Эннеаграмма, Большая пятёрка) — использовать `higher_is_better` + переинтерпретацию + топ-N как главный результат.

## Что сработало

1. **Линтер `npm run check:chats` прошёл с 0 errors с первого раза** — впервые в истории платформы (из 8 предыдущих книг ни одна не проходила линтер с первого захода). Это благодаря строгому следованию runbook на этапе seed-дизайна и обоим контрпримерам в каждом промпте (склейка через пробел + угловые скобки).

2. **12 шкал на радаре с группировкой по 4 секторам** — визуально считывается сразу. Group order на радаре: Оставить След (12 часов) → Структурирование (3 часа) → Принадлежность (6 часов) → Тоска по Раю (9 часов).

3. **Темы 1:1 с группами архетипов** — каждая из 4 тем ведёт в режим «Архетип твоего бренда» с подмешанным контекстом группы. Темы сортируются на хабе по баллам теста (test_scale_key мапится на представителя группы — Простодушный/Герой/Славный Малый/Заботливый).

4. **24 вопроса вместо 36** — с 1 direct + 1 reverse на каждый архетип. Хватает для устойчивого профиля при коротком прохождении (~7 минут). Психометрически слабее 36, но критичнее retention — длинные тесты теряют пользователей.

5. **Двойное прочтение книги** — режимы «Архетип твоего бренда» и «Твой личный архетип» как отдельные. Не пытался слить «определи архетип чего угодно» — это сделало бы каждый разбор поверхностным. Метод «Артишок» (5 фаз) применим именно к бренду, не к личности — поэтому два разных режима с разной механикой.

6. **Кэрол Пирсон как author_chat, не Маргарет Марк** — Пирсон создательница системы и автор «Hero Within» (про личные архетипы). Один голос проще для пользователя (как в pishi-sokraschay — только Ильяхов). Маргарет упомянута в системных промптах как соавтор.

7. **Все иконки уже были в INSTRUMENT_ICON_MAP** — не пришлось рисовать новые SVG. Для THEME_ICON_MAP добавил 4 ключа (`arch_paradise`, `arch_impact`, `arch_belonging`, `arch_order`) — все переиспользуют существующие компоненты (CompassIcon, RocketIcon, HeartLoveIcon, ShieldIcon).

## Что пришлось изобретать на ходу

1. **Переинтерпретация `higher_is_better` для нейтрального профиля.** Седьмое правило тона Пирсон («не патологизировать») для архетипного теста ещё строже — потому что архетип Бунтаря в 30% или в 80% оба нормальны. Запрет на слова «синдром / нарушение / проблема» — однозначный. Используем только «архетип / качество / грань / сторона / направление / зона».

2. **Топ-2 архетипа из 12 как главный результат.** В предыдущих тестах главным показателем был level_label или взвешенная шкала. Здесь — просто два названия архетипов крупно: «У тебя сильны Бунтарь и Творец». Это требует адаптации `interpretation_prompt` — top_zones теперь не «зоны риска», а «ведущий профиль».

   **Уточнение (май 2026):** для типологий используется **расширенный формат top_zones** — `{ scale_key, score, headline, body, action_text, action_route }`. Поле `scale_key` — внутренний ключ архетипа (`impact_hero`, `belonging_lover` и т.д.), **НЕ русское имя**. Если промпт выдаёт `archetype: "Любовник"` — UI не сможет резолвить процент и иконку (баг #12 в PLATFORM_MAP). Русское имя — в `headline` и `body`. Полная схема — раздел «Формат top_zones» в `references/PLATFORM_MAP.md`.

3. **Маппинг шкала → режим через group representative.** test_scale_key темы — это конкретный архетип-представитель группы (например, для группы «След в мире» — `impact_hero`), хотя группа объединяет 3 архетипа. Это упрощение для сортировки тем, но в welcome_system_context темы я указываю всех 3 архетипов группы и AI работает со всей тройкой.

4. **Локальная обложка вместо Литрес.** На Литрес книга 2005 года Питер не нашлась с прямым URL. Скачал маленькое превью с лабиринта (новое издание МИФ 2024) в `public/books/heroes-and-outlaws.jpg`. По-хорошему, нужна обложка получше — это open question для будущей доработки.

## Открытые вопросы (на будущее)

1. **Обложка лучше.** Сейчас 10KB превью с лабиринта. Найти/сделать качественную 415px обложку и заменить файл `public/books/heroes-and-outlaws.jpg`.

2. **Маргарет Марк как второй author_chat.** Если данные покажут спрос на «маркетолог-практик» (а не Пирсон-психолог) — добавить второй author_chat с Маргарет Марк, упор на Fortune 500 кейсы.

3. **Книга «Awakening the Heroes Within» как отдельная программа.** Это книга Пирсон про путь индивидуации через 12 архетипов в личной жизни — без брендов. Если данные покажут, что пользователи в режиме `arch_self` проводят больше времени, чем в `arch_brand` — стоит сделать отдельную программу про личный архетип, оставив текущую только для брендов.

4. **Калибровка level_thresholds после 30+ прохождений.** Сейчас стандартные `[25, 50, 75]`. Возможно, для архетипов нужно сместить — большинство людей даёт 30-70% по большинству архетипов, поэтому пороги «В тени < 25 / Доминирующий > 75» могут оказаться слишком жёсткими. Подкручивать после реальных данных.

5. **dev-login падал с 500.** В worktree `/api/auth/dev-login` вернул 500 (вероятно проблема с Service Role Key в env). Не блокирует продакшен — лендинг и SQL-операции работают. Нужно отдельно отладить dev-login в worktree-окружении.

## Уроки для следующих книг

1. **Третий формат теста — нейтральный профиль.** Если книга про типологию/архетипы/стили — `higher_is_better` с переинтерпретацией + топ-N архетипов как главный результат. Не патологизировать никакой из шкал.

2. **Линтер с первого раза — реально.** Если строго следовать runbook: `welcome_ai_message` plain text без markdown, `welcome_replies` объекты `{text, type}` с exit, оба контрпримера в каждом system_prompt — линтер пройдёт без fix-*.sql.

3. **Для не-психологических книг — двойное прочтение.** «Пиши, сокращай» = только копирайтинг. «Герой и Бунтарь» = бренды + личность. Если книга шире одного домена — два-три отдельных режима под разные применения, не один универсальный.

4. **Один автор в author_chat при нескольких авторах** — выбирай **создателя метода**, не маркетолога-партнёра. Пирсон создала систему, Марк её упаковала для бизнеса. Голос Пирсон сильнее для AI-симуляции.

5. **Группировка шкал на радаре — не группа = шкала.** 12 шкал (по 1 на архетип) красивее и точнее, чем 4 (по группам). Группы — это визуальные секторы на radar и сортировка тем, но сами шкалы — мельче.

6. **Для тестов на профиль — топ-N результат.** Не заставляй пользователя смотреть на 12 уровней — выдели топ-2 (или топ-3) как «это про тебя». Радар — для тех, кто хочет деталей.

7. **WebFetch для фото авторов работает.** Проверено: достаточно сайта автора + page «about» — фото всегда рядом. Скачать через PowerShell `Invoke-WebRequest`, сохранить в `public/authors/<slug>.{webp|jpg}`, прописать локальный путь в landing_data.author.photo_url.
