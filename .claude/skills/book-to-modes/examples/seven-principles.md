# Конспект решений: 7 принципов крепкого и счастливого брака (Готтман)

**Slug:** `seven-principles`
**Тип:** Терапия-отношения + навыки (научный фреймворк)
**Объединение:** Нет — одна книга (7 принципов самодостаточны как канон)
**Дата:** 2026-05-15 (8-я книга платформы)
**Тест slug:** `marriage-map`, навыковый формат (`higher_is_better`)

## Книга

John Gottman, Nan Silver. «The Seven Principles for Making Marriage Work» (1999, переизд. 2015). Канонический перевод РУ — «7 принципов крепкого и счастливого брака» (МИФ, 2018).

Структура:
- I. Что такое крепкий брак (Love Lab, 4 всадника, repair attempts, flooding)
- II. 7 принципов с опросниками и упражнениями:
  1. Карты любви
  2. Нежность и восхищение
  3. Поворот к партнёру
  4. Принимать влияние партнёра
  5. Решать решаемые проблемы (мягкий старт)
  6. Преодолевать тупик (скрытая мечта)
  7. Создавать общий смысл (4 столпа)

## Главное решение: одиночный формат для книги о двоих

Книга работает только когда оба партнёра в зале. Тренажёр — для одного. Адаптация:
- **Карта любви** → проверить что пользователь знает о партнёре + готовый список «что спросить за ужином»
- **Разбор ссоры** → пользователь приносит свежий конфликт фактами, AI находит 4 всадников и переформулирует обвинительные фразы
- **Репетиция разговора** → AI играет партнёра (сначала спокойно, потом защитно). Маркер `💡 Совет` отделяет роль партнёра от обратной связи
- **Восхищение** → упражнения «I appreciate» из главы 5, переписать историю отношений + список 100 качеств
- **Скрытая мечта** → метод «Dreams Within Conflict» — найти детскую мечту за тупиком (не решить, а услышать)
- **Смысл пары** → 4 столпа Готтмана собранные в персональную карту

Решение принимать книгу самодостаточной и не объединять с другими работами Готтмана («What Makes Love Last», «And Baby Makes Three») — каждая из его книг канон сам по себе.

## Решение: навыковый тест (не диагностический)

7 принципов — это **навыки**, не «синдромы». Высокий балл = принцип хорошо работает. Низкий = зона роста, не патология. Это идеально под `score_direction: higher_is_better`, как у Бредберри EQ 2.0.

Уровни: «Зона роста / Развивается / Устойчиво / Сильная сторона» — без клинической рамки. Пороги `[40, 60, 80]` — сдвинуты вправо, чтобы «Сильная сторона» не давалась слишком легко.

28 вопросов = 7 шкал × 4 вопроса (3 direct + 1 reverse). Все утверждения взяты из готовых опросников Готтмана к каждому принципу. Это первый случай на платформе, когда тест составлен **полностью из авторских опросников** — без реконструкции.

## Что сработало

1. **7 готовых опросников = 7 готовых шкал.** Не пришлось придумывать вопросы — Готтман уже сам их откалибровал на тысячах пар. Просто перевели True/False в 5-балльный Ликерт.

2. **Ключевая позиция в каждом промпте.** Фраза «никаких приговоров, в любых отношениях это бывает, разница не в наличии, а в пропорции и в умении чинить» — вшита в системные промпты всех режимов. Это спасает от обвинительного тона.

3. **Гендерно-нейтральные формулировки `сказал(а)`, `почувствовал(а)`** — ЦА чаще женщины, но не только. Не предполагаем пол партнёра пока пользователь сам не назвал.

4. **Разделение ролей в режиме Репетиция через маркер `💡 Совет`.** AI играет партнёра — обычным текстом. Обратная связь — отдельным блоком после «💡 Совет:». Это паттерн из EQ 2.0, перенесённый сюда.

5. **Все нужные иконки уже были на платформе** — `map`, `search`, `drama`, `heart`, `sparkles`, `compass`, `check`. Новые рисовать не пришлось.

6. **Линтер `npm run check:chats` прошёл с первой попытки** — без фиксов после первичного seed. Учтены все 6 типовых fix-паттернов: counterexample про склейку, counterexample про угловые скобки, plain-text welcome без markdown, объекты в welcome_replies, последний reply = exit, локальный путь photo_url.

7. **3 параллельные миграции через MCP `apply_migration`** вместо одного гигантского запроса. Поделил по логическим частям: программа → шаблоны+чаты → 3 режима → ещё 3 режима → тест. Если бы что-то упало, было бы понятно где.

## Что пришлось изобретать

1. **ID обложки на Литрес.** Изначальный ID 8718995 был выдуман — выдал 404. Через WebSearch нашёл правильный ID 28544026 (русское издание «7 принципов счастливого брака, или Эмоциональный интеллект в любви»). Урок: обложки **обязательно проверять до первого деплоя** через прямой GET к cdn.litres.ru.

2. **Race condition при автотесте теста.** При автокликах ответов через preview_eval несколько POST /api/test/answer уходят параллельно — возвращают 409 Conflict. В реальном использовании юзер не кликает с такой скоростью, но если будем автоматизировать e2e тестирование — нужна задержка 1.5-2 секунды между ответами или ожидание ответа предыдущего запроса.

3. **session_create_failed на первом ответе анонимного теста.** Возможно race в `app/api/test/_handlers/anonymous.ts` — повторный POST когда сессия ещё создаётся. Не блокирует прохождение, но логи Sentry будут засоряться. Стоит посмотреть отдельно (`mcp__ccd_session__spawn_task`).

## Что заняло больше всего времени

1. Чтение 7 глав книги, чтобы выдернуть концепции и упражнения каждого принципа — ~25 мин
2. Написание 6 системных промптов режимов (каждый ~3 KB) — ~30 мин
3. Сборка теста из 28 утверждений — ~15 мин
4. Поиск правильного ID обложки на Литрес — ~10 мин (можно было сэкономить если бы сразу проверил через GET)
5. Применение SQL по частям через MCP — ~10 мин

## Уроки для следующих книг

1. **Проверять URL обложки Литрес через прямой GET до seed**. Если 404 — искать через WebSearch.
2. **При prefix-именовании шкал и режимов не пересекаться** — у меня в режимах `sp_shared_meaning`, в шкалах теста — то же название. Это не сломало (разные таблицы), но в будущем стоит для шкал использовать суффикс типа `_scale` чтобы не путать.
3. **Готтмановский тон работает и для других книг по отношениям** — нормализация, презумпция нормы, опора на цифры. Можно переиспользовать в книгах про семью.
4. **Гендерно-нейтральные формулировки с `(а)` в окончаниях** — проверенный паттерн для книг с женской ЦА.
5. **Книга-канон с готовыми опросниками = тест почти бесплатно**. Если у автора есть валидированные шкалы — это лучший источник для теста.

## Открытые вопросы

1. **Длинный hub_messages.first** — может оказаться длинноват. Откалибровать после первых прохождений.
2. **Тест retest** — нет explicit-CTA «попробуй заново через 2-3 месяца». Можно добавить в результатах.
3. **program_themes для семи шкал** — пока не созданы. Hub_messages.returning_test использует {theme1}/{theme2} — без program_themes плейсхолдеры стрипаются, всё ОК. Но если хочется персонализации на хабе через темы — нужно добавить.
4. **session_create_failed на анонимном тесте** — race condition в `/api/test/answer`. Отдельная задача.
