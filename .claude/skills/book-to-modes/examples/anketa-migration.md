# Шаблон: миграция chat-калибровки → анкета

Этот файл — **не ретроспектива конкретной книги**, а готовый рабочий шаблон для замены устаревшего chat-калибратора (`<book>_calibration` mode) фуллскрин-анкетой на существующей книге платформы. Отличается от создания книги с нуля: программа, лендинг, темы, режимы и прочее уже в БД — добавляем только User-level анкету и снимаем старый режим с программы.

**Прецеденты:** `pishi-sokraschay` (Ильяхов, май 2026), `borba-za-vnimanie` (Белоусов, май 2026). Шаблон проверен на двух книгах, миграционный план завершён.

## Когда применять (быстрая проверка)

| Условие | У тебя |
|---|---|
| Программа уже на платформе (есть лендинг, режимы, hub_messages) | … |
| У книги есть `program_modes` с `chat_type LIKE '%_calibration'` ИЛИ другой chat-режим, выполняющий функцию настройки тренажёра в 2-4 обмена | … |
| Slug книги нет в `AnketaProgramSlug` (анкета ещё не подключена) | … |
| Книга **не** одно-тематическая (Кехо «Подсознание» — пропускаем, см. SKILL.md §«Когда НЕ делать анкету») | … |

Если все 4 «да» — мигрируем по шагам ниже.

## 4 шага миграции

### Шаг 1. Добавить вопросы в каталог

В [`lib/anketa/questions.ts`](../../../../lib/anketa/questions.ts):

1. Расширить тип `AnketaProgramSlug` ключом нового slug.
2. Добавить 3 вопроса в `ANKETA_QUESTIONS[<slug>]` по SPIN-структуре (`context_intent` / `problem` / `need_payoff`).

**Формулировки — под тип книги.** См. таблицу в [SKILL.md → «Формулы 3 вопросов под разные типы книг»](../SKILL.md). Главное:

- chipLabel — 2-4 слова, label — полное предложение от первого лица, не вопрос.
- Тон совпадает с тоном автора книги (см. таблицу «Тон вопросов = тон автора»).
- Старая chat-калибровка обычно уже содержит готовые формулировки — переиспользуй их как сырьё, но переформатируй в SPIN (chip → label → placeholder).

**Пример из Ильяхова** (`pishi_calibration` имел 3 открытых вопроса — взяли как основу, добавили 4 чипа с уровнями пирамиды):

```typescript
"pishi-sokraschay": [
  {
    id: "context_intent",
    type: "hybrid",
    title: "Что у тебя болит с текстами?",
    options: [
      { value: "purpose", label: "Не понимаю, для кого и зачем пишу — додумываю в процессе", chipLabel: "не вижу цели" },
      { value: "thesis",  label: "Получается водянисто — главное теряется среди деталей",      chipLabel: "много воды" },
      { value: "structure", label: "Тексты длинные — не дочитывают, нет нормального заголовка", chipLabel: "не дочитывают" },
      { value: "style",   label: "Канцелярит и штампы — хочу писать по-человечески",            chipLabel: "канцелярит и штампы" },
    ],
    placeholder: "Например: пишу лендинги, но конверсия слабая…",
  },
  // ... problem + need_payoff в тоне автора
],
```

### Шаг 2. Прописать `hub_messages` в БД

Через `mcp__supabase__execute_sql`. Для книги без теста (типичный случай миграции с калибровки) — Вариант A из [SKILL.md → «Шаблон hub_messages»](../SKILL.md):

```sql
UPDATE programs SET hub_messages = jsonb_build_object(
  'first',
    '[приветствие первого визита + приглашение в анкету (2 минуты)]',
  'anketa_only',
    'Помню твой запрос — <strong>{problem}</strong>. [Предложение 2-3 конкретных инструментов автора в тоне книги — не «выбери режим», а «можем разобрать X, собрать Y или пройти Z. С чего зайдём?»]',
  'returning_notest',
    '[возврат без анкеты + предложение её пройти ("2 минуты на анкету — следующие чаты будут точнее") + выбор инструмента справа]',
  'returning_test',
    'С возвращением. По твоему запросу — <strong>{problem}</strong>. Что разбираем сегодня?',
  'anketa_and_test',
    'Помню твой запрос — <strong>{problem}</strong>. Готов продолжить?'
) WHERE slug = '<BOOK_SLUG>';
```

`returning_test` и `anketa_and_test` — safe fallback на случай если когда-то добавят тест. Стоит 2 строки SQL, защищает от регрессий.

### Шаг 3. Снять старый режим с программы

```sql
DELETE FROM program_modes
WHERE program_id = (SELECT id FROM programs WHERE slug = '<BOOK_SLUG>')
  AND mode_template_id = (SELECT id FROM mode_templates WHERE key = '<book>_calibration');
```

**Не трогать:**
- `mode_templates.key = '<book>_calibration'` запись — оставь в каталоге на случай отката.
- Чаты с `chat_type='<book>_calibration'` в `messages` — нужны для аудита; фронт их не отрисует, потому что режима в `program_modes` больше нет.
- `<book>_calibration` в `CALIBRATION_CHAT_TYPES` в [`lib/chat/prepare-context.ts`](../../../../lib/chat/prepare-context.ts) — старые чаты могут оставаться у пользователей, которые ещё не заполнили анкету; пусть подмешивается.

### Шаг 4. Smoke-test (9 пунктов)

После применения шагов 1-3 пройди вручную (можно через `?hub_state=...` debug-параметры):

1. `/program/<slug>/hub` для нового пользователя → auto-redirect на `/anketa` (через `isAnketaProgram(slug)`).
2. Анкета фуллскрин, 3 шага, прогресс 1→2→3, Skip справа.
3. Чип в Q1 заполняет полный label в textarea; ответы в Q2/Q3; submit → возврат на хаб.
4. Welcome AI в состоянии `anketa_only` ссылается на `{problem}` (обрезано через truncatePhrase), тон книги. Grammar не ломается.
5. Старый режим «Настройка тренажёра» / «Калибровка» **исчез** из хаба. Инструменты начинаются с **flagship-режима** программы (например, `belousov_contexts` или `pishi_thesis_seeker`).
6. Чат любого инструмента открывается, в системном промпте есть блок «КТО ПЕРЕД ТОБОЙ» с тремя ответами анкеты (можно проверить через `appendDevTrace` или просто по поведению AI).
7. `/program/<slug>/portrait` — секция «Твой запрос из анкеты» с тремя полями.
8. Если у книги нет `program_themes` — на хабе нет секции «Темы» (нормальный кейс).
9. В `user_profile_responses` 3 записи: `context_intent` / `problem` / `need_payoff`, `source='anketa'`, `version=1`.

Образец прогона по 9 пунктам — `examples/borba-za-vnimanie.md` (раздел «Smoke-test»).

## Что НЕ делать (явные anti-patterns)

- ❌ **Не удалять `mode_templates.key = '<book>_calibration'`** — потеряешь возможность отката одной строкой.
- ❌ **Не делать backfill** старых калибровочных чатов в `user_profile_responses`. Это было обсуждено, решили не делать — пользователи которые проходили старую калибровку и не зашли в анкету, останутся с подмешиванием через `appendCalibrationContext`. См. ADR.
- ❌ **Не добавлять новый chat-калибратор** под другим именем для другой книги. Это anti-pattern (см. SKILL.md → «Anti-pattern: chat-калибровка как отдельный режим тренажёра»). Если кажется что анкета не покрывает — обсуждай расширение анкеты или flagship-режима, не клонируй калибратор.
- ❌ **Не «дозаполнять» program_themes ради плейсхолдеров.** Если у книги нет тем (Ильяхов, Белоусов) — `{theme1}`/`{theme2}` стрипаются автоматически, fallback на `returning_notest` работает. Не выдумывай темы только чтобы плейсхолдер показал что-то.

## Что должно быть в итоговом отчёте

Когда миграция готова, по образцу borba-za-vnimanie сохраняешь ретроспективу в `examples/<book_slug>.md` (если её ещё нет) или дописываешь раздел в существующую. Минимум:

1. Какие 3 вопроса добавил (с обоснованием тона).
2. Какие 5 ключей `hub_messages` прописал.
3. Какой режим снял с `program_modes` (имя, ON CONFLICT поведение).
4. Результаты smoke-test (9 пунктов).
5. Чем отличается от предыдущих миграций (если есть отличия — это вход для скилла).
