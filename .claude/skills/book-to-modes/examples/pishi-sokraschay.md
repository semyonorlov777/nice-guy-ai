# Конспект решений: Пиши, сокращай (Ильяхов / Сарычева)

**Slug:** `pishi-sokraschay`
**Тип:** Маркетинговая / практическая (редактура, информационный стиль, копирайтинг)
**Объединение:** Нет — одна книга
**Дата:** Май 2026 (восьмая книга платформы; **первая не-психологическая**)

## Книга

Максим Ильяхов и Людмила Сарычева. «Пиши, сокращай: как создавать сильный текст». АП, 2017. 440 стр. Тираж 500 000+ за 7 лет. Бестселлер по редактуре.

## Особенность задачи

Первая на платформе книга не по психологии. Все 7 предыдущих (Гловер, Берн, Чепмен, Бакиров, Бредберри, Гулдинги, Осипов) — терапевтические или практико-психологические. Здесь — навык: редактура, копирайтинг, инфостиль.

## Главное открытие из доп. ресурсов: ПИРАМИДА КОММУНИКАЦИИ ИЛЬЯХОВА

В книге разбиение на 3 части: «Отжать воду» (стоп-слова), «Донести мысль» (структура), «Рассказать о себе» (продающие тексты). Это **внешняя** структура.

В YouTube-курсе «Базовый курс сильного текста» (19 видео, soviet.glvrd.ru/hello → плейлист `PLFc6c8XU7GL2KTRGLAWs4NjqxFNdztcMX`) Ильяхов явно рисует **внутреннюю** структуру — пирамиду коммуникации, по которой он рекомендует работать СВЕРХУ ВНИЗ:

| Уровень | Что | Куда легло в книге |
|---------|-----|--------------------|
| 1. Полезное действие — **Царь горы** | Кому и зачем нужен текст? | Главы «Знакомство», «Главный секрет» |
| 2. Формулирование мысли | Тезис → аргументы → план | Часть 2 «Цель и задачи», «Структура» |
| 3. Визуализация | Сначала покажи, потом расскажи | В книге слабо подсвечено |
| 4. Структура и подача | Заголовок, абзацы как навигация | Часть 2 «Заголовок», «Абзацы» |
| 5. Синтаксис | «Человек делает так» | Часть 2 «Синтаксис», «Однородные» |
| 6. Слова | Стоп-слова: вводные, оценки, штампы | Часть 1 «Отжать воду» (вся) |

**Решение:** строить режимы тренажёра НЕ по внешним частям книги, а по пирамиде Ильяхова. Это его авторский каркас, более точный для тренажёра, чем оглавление книги.

Без видео-курса я бы построил режимы по 3 частям книги — и упустил бы главную авторскую модель. Урок: для книг с публичным курсом автора — обязательно проверять курс, даже если кажется что в книге достаточно.

## Главный архитектурный урок: КАЛИБРОВКА ВМЕСТО ТЕСТА

Пользователь сразу заявил, что классический ликерт-тест ему не нужен — лучше «3 быстрых открытых вопроса чтобы настроить тренажёр-практикум».

Архитектурно это **новый паттерн** на платформе:

- НЕ через `test_configs` — это не тест с ликерт-шкалой
- НЕ через отдельный route — это обычный chat-режим (`pishi_calibration`, chat_type=`pishi_calibration`)
- system_prompt режима строго ведёт через 3 открытых вопроса (результат / профессия / сложности) и в финале завершает фразой `[КАЛИБРОВКА ЗАВЕРШЕНА]`
- В коде добавлена функция `appendCalibrationContext(supabase, systemPrompt, userId, programId, currentChatType)` в `lib/chat/prepare-context.ts` — она ищет последний чат типа `pishi_calibration` и подмешивает первые 6 сообщений (3 пары вопрос-ответ) во все остальные системные промпты программы
- Вызов добавлен в `app/api/chat/route.ts` после `appendTestScores`. NЕ вызывается для самого режима калибровки — иначе self-reference

**Преимущества:** не нужны новые таблицы, миграции БД, логика парсинга и хранения ответов. Используется существующая инфраструктура чатов.

**Прецедент:** этот паттерн может пригодиться для следующих маркетинговых/практических книг, где классическая диагностика не работает.

## Что сработало

1. **Транскрибации видео-курса** дали структуру пирамиды и тон Ильяхова — то, что не извлекалось из книги. Пользователь сам предоставил транскрибации первых 11 из 19 видео — без этого режимы были бы построены по «внешней» структуре книги.
2. **Калибровка как первый chat-режим с бейджем «Сначала это»** — естественный onboarding без архитектурных изысков.
3. **Тон Ильяхова** удалось передать через конкретные речевые маркеры: «ребята», «штука», «вот это вот всё», «короче», «болезнь умных людей». Без видео эти маркеры не вытащить — в книге язык чище.
4. **«Дерзкий коуч» вместо «бережного наставника»** — впервые на платформе (все предыдущие книги были терапевтические). Эта матрица из REFERENCE.md секция 2 сразу легла на стиль Ильяхова.
5. **Локальное хранение медиа** — обложка с cdn.litres.ru (внешний URL, разрешён в CSP), фото автора с Wikipedia Commons → в `/public/authors/ilyahov.jpg`. Никаких CSP-сюрпризов.
6. **Линтер `npm run check:chats` прошёл с 0 ошибок с первого раза** — благодаря строгому следованию runbook'у на этапе seed-дизайна. Из 6 предыдущих книг ни одна не прошла линтер с первого захода.

## Что пришлось изобретать на ходу

1. **`appendCalibrationContext` функция** — нового кода в `lib/chat/prepare-context.ts` не было прецедента. Сделана по аналогии с `appendPortraitContext` и `appendTestScores`, но с дополнительной защитой от self-reference (если текущий режим — сама калибровка, не подмешиваем).
2. **3 новые иконки** — `Brain`, `Layout`, `Eraser`. Добавлены и в `mode-icons.tsx` (для NewChatScreen), и в `hub-icons.tsx` (для InstrumentList), и в маппинги обоих файлов. Это два разных набора иконок в проекте — обязательно держать синхронно.
3. **«Зачем этот текст» как отдельный режим** — этого уровня нет в каркасе REFERENCE.md (там 5 архетипов: Лекция, Анализ, Воркшоп, Ролевая, Экзамен). Сделан как «Воркшоп», но содержательно — это исследование цели. Может пригодиться для следующих маркетинговых книг.
4. **Эталоны из книги в режиме «До/После»** — собрал 6 пар «было / стало» прямо в system_prompt режима. Это работает как опорный материал для AI: он не выдумывает плохие тексты, а использует подтверждённые авторские примеры.

## Что заняло больше всего времени

1. Чтение книги Explore-агентом + сбор 45 цитат (~15 мин)
2. Применение пользователем транскрибаций 11 видео + интеграция в план (~20 мин — большой объём текста)
3. Написание system_prompt для 7 режимов с соблюдением всех правил runbook'а (~25 мин)
4. SQL миграции через MCP по одной на режим (~10 мин)

## Открытые вопросы и идеи

1. **Оставшиеся 8 видео курса** — пользователь дал 11 из 19. Если в оставшихся видео (про продающие тексты, регалии, Часть 3 книги) есть ценные приёмы — режим «Тренажёр До/После» можно расширить новыми категориями.
2. **Author chat только с Ильяховым** — Сарычева упомянута как соавтор в about-секции, но в чате её нет. По решению пользователя — упрощение для пользователя (один голос). Если данные покажут спрос на разговор с Сарычевой — можно добавить второй author_chat.
3. **Калибровка пока работает только для pishi-sokraschay** — `CALIBRATION_CHAT_TYPES` в коде содержит только `pishi_calibration`. Если паттерн пригодится другим книгам — расширить массив (или сделать через features-flag в programs).
4. **Нет ликерт-теста** — программа без воронки в формате «пройди тест → узнай свой архетип». Это сознательное решение для маркетинговой книги. Если данные покажут что воронка нужна — можно добавить миниатюрный тест на лендинге (3-5 вопросов про типы текстов).

## Уроки для следующих книг

1. **Если у автора есть публичный курс/видео** — обязательно проверь, не противоречит ли структура курса структуре книги. Часто курс — более «свежая» и продуманная упаковка авторской модели.
2. **Для маркетинговых/практических книг** — пирамида / иерархия уровней работы лучше, чем линейные «части книги». Это даёт пользователю понятный путь «сверху вниз».
3. **Калибровка через chat-режим** — если книга не диагностическая, лучше короткий открытый onboarding, чем 25-вопросный ликерт. Архитектурно — `appendCalibrationContext` в prepare-context.
4. **Иконки в двух местах** — `mode-icons.tsx` (для NewChatScreen) И `hub-icons.tsx` (для InstrumentList). Не забыть оба + два маппинга.
5. **Тон автора** — конкретные речевые маркеры в author_chat_system_prompt (не описание стиля «разговорный», а буквальные выражения). Их легко найти в видео, сложно вытащить из книги.
