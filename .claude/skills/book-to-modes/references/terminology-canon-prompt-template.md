# Terminology canon — шаблон двух Deep Research

> Используется на **Этапе 1.5** (`SKILL.md` → «Terminology canon checkpoint») для книг с насыщенной профильной терминологией (CBT, гипноз, специализированный коучинг, медицина, право, философия, и т.д.).
>
> Цель — получить **единый русскоязычный канон** до проектирования режимов / теста / лендинга, чтобы потом не переписывать всю программу.
>
> Прецедент применения: `docs/books/transdiagnostic-cbt-terminology-canon-unified.md` (синтез Claude + Gemini, 2026-05-19).

---

## Когда не использовать этот шаблон

- Self-help / motivation / общая публика (Гловер, Кехо, Радикальное прощение) — русские эквиваленты устоявшиеся, канон не нужен.
- Книга по бытовой теме (отношения, родительство, привычки) без специализированных терминов.
- В книге <10 терминов, у которых неочевиден русский эквивалент.

Подробные критерии срабатывания — `SKILL.md` § Этап 1.5.

---

## Что AI делает ПЕРЕД запуском двух DR

1. **Составить список терминов**, по которым нужен канон. Минимум 20-30, максимум 60. Включай:
   - Структурные термины модели книги (как автор называет главные строительные блоки)
   - Технические/конструктные термины (acronyms, особые понятия)
   - Названия методик / интервенций / практик
   - Названия опросников / тестов / шкал (с акронимами)
   - Категории, по которым книга классифицирует феномены
2. **Найти конкурирующие русские источники** в области. Это не сама задача DR — это твоя домашняя работа до запуска:
   - Какие русскоязычные академические школы есть (вузы, ассоциации)?
   - Какие профильные журналы публикуют переводные статьи?
   - Кто из переводчиков переводил классиков поля на русский?
   - Есть ли официальные русские переводы базовых книг (Beck, Linehan, Hayes, Wells, …)?
3. **Зафиксировать дисамбигуацию автора** (см. REFERENCE.md §12 «Правила атрибуции»):
   - Однофамильцы — исключить
   - Смежные книги того же автора — допущены / запрещены / помечать отдельно
4. **Подставить плейсхолдеры** ниже:
   - `{{BOOK_TITLE}}` — название книги полностью
   - `{{BOOK_AUTHORS}}` — авторы (ФИО, год издания)
   - `{{BOOK_YEAR}}` — год издания
   - `{{ISBN}}` — ISBN основной редакции
   - `{{FIELD}}` — область («когнитивно-поведенческая терапия» / «эриксоновский гипноз» / «специализированный коучинг» / «уголовное право», и т.д.)
   - `{{TARGET_AUDIENCE}}` — кто будет читать промпты Gemini в тренажёре (practicing psychologists / advanced students / certified coaches / practicing lawyers / etc.)
   - `{{RUSSIAN_SOURCES_HINT}}` — 5-10 строк с конкретными русскоязычными источниками для DR (ассоциации, журналы, переводчики). Чем конкретнее — тем точнее канон.
   - `{{TERMS_LIST}}` — пронумерованный список терминов из шага 1 (30-50 штук). Каждый английский термин — на отдельной строке.
5. **Запустить ОБА DR независимо** (не один за другим — параллельно, чтобы они не контаминировали друг друга через твою редактуру промпта).

## Что AI делает с РЕЗУЛЬТАТАМИ двух DR

1. **Сохрани каждый DR отдельно** для трассируемости:
   - `docs/books/{slug}-terminology-canon-claude.md` — резюме Claude Research (5-15 строк TL;DR + ссылка на unified)
   - `docs/books/{slug}-terminology-canon-gemini.md` — резюме Gemini Research (5-15 строк TL;DR + ссылка на unified)
   - Полные сырые тексты — оставь в чате сессии или в виде приложения

2. **Сопоставь два канона построчно.** Где расходятся:
   - Один даёт RUSSIAN_STANDARD, другой HYBRID — обычно выигрывает более консервативный (HYBRID, защитное решение)
   - Разные русские варианты для одного термина — выбирай тот, у которого источник авторитетнее (официальный перевод базовой книги > журнальная статья > глоссарий ассоциации)
   - Один даёт термин, другой нет — добавь в канон, отметь что у одного из research'ей пробел
   - Один даёт запрещённый перевод, которого нет у другого — обязательно добавь (запреты не отбрасывать)

3. **Создай unified canon document** по образцу `docs/books/transdiagnostic-cbt-terminology-canon-unified.md`. Обязательные секции:
   - **Метаправило для правки** — как канон применяется к разным полям БД (system_prompt vs welcome vs replies vs landing vs test_configs)
   - **Правило первого упоминания** — для HYBRID-терминов
   - **Финальный канон по категориям** — таблицы по тематическим группам (структурные / когнитивные / поведенческие / методики / опросники / специальные)
   - **Запрещённые переводы** — таблица с клиническими/смысловыми ошибками
   - **Главные методологические принципы** — 5-7 штук из обоих research'ей
   - **Применение к полям БД** — пронумерованный список с приоритетами правки
   - **Контекстные исключения** — где канон не применяется (имена клиентов из книги, цитаты, библиография)
   - **Что НЕ менять** — имена авторов, технические ключи в БД, JSON-структуры
   - **Ссылки на полные research** — пути к двум исходным файлам

4. **Сохрани unified** как `docs/books/{slug}-terminology-canon-unified.md`.

5. **Покажи unified пользователю.** Только после его подтверждения переходи к Этапу 2 (маппинг на архетипы) — режимы должны строиться уже на правильной терминологии.

## Антипаттерны при составлении канона

- ❌ **«AI справится сам — переведём на лету»** — без канона разные режимы используют разные термины, тест говорит «когнитивные искажения», лендинг — «искажения мышления», welcome — «cognitive distortions». Пользователь видит несогласованность.
- ❌ **«Возьмём перевод из Google Translate»** — машинный перевод регулярно даёт бытовые значения для технических терминов («safety behaviour» → «безопасное поведение», ассоциация с ОБЖ, а не клиническое «охранительное поведение»).
- ❌ **«Один DR хватит»** — один research систематически промахивается в одной области (или в дисамбигуации автора, или в опросниках). Два независимых research'а ловят разные пробелы.
- ❌ **«Канон только для system_prompt»** — пользователь не читает system_prompt, читает welcome/replies/landing. Канон должен покрывать видимые поля в первую очередь.
- ❌ **«Запрещённые переводы — необязательная секция»** — это самая важная часть канона. Без неё AI генерирует тексты с типичными бытовыми ошибками («core beliefs» → «базовые убеждения» вместо «глубинные убеждения»).
